# Working in this Jac project

This is a [Jac](https://www.jaseci.org/) project. Jac's syntax has evolved and
is easily confused with Python or JSX -- before writing or editing `.jac`
files, consult the reference guides bundled with the compiler.

## Reference guides

The `jac` CLI ships curated reference guides ("Agent Skills") -- the
authoritative spec for writing correct, idiomatic Jac:

- `jac guide` -- list every available guide
- `jac guide <name>` -- print a guide (e.g. `jac guide jac-types`)
- `jac guide --search <keyword>` -- find guides by topic
- `jac guide --json` -- machine-readable output for tooling

Start with `jac guide jac-core-cheatsheet` and `jac guide jac-types`.

## Validate your work

- `jac check <file>` -- type-check and lint. Compiler diagnostics link to the
  relevant guide; follow the `-> run 'jac guide ...'` hints.
- `jac run <file>` -- execute a Jac program.

## Tests

Two layers, run both before shipping a server-side change:

- **Unit + integration** -- one `<mod>.test.jac` annex per module (pure
  parsers in `metrics`/`data`, graph CRUD + multi-tenant isolation in
  `persistence`, the `jms_*` product modules). No running server needed. The
  annex sits beside its module under `server/<pkg>/`; run one FROM THE REPO ROOT
  with `jac test server/<pkg>/<mod>.test.jac` (from another cwd, `server.*`
  imports fail). Graph tests share a persisted root -- run them from a copy of
  the repo, never against the live `.jac/data`.
- **Smoke (live server)** -- `scripts/smoke.sh` (boot check) and
  `scripts/smoke_auth.sh` (auth isolation) hit a running browser-target API
  (`jac start --dev main.jac`).

## Layout

See README.md. `server/{core,models,jms,cloud}/` (each dir needs its empty
`__init__.jac` so `jac check`/`jac test` resolve `server.*`), `client/` (UI +
`styles/`), `scripts/` (workers, smoke, backup). New server module = file under
`server/<pkg>/` + its import in `main.jac`; import siblings as
`import from server.<pkg> { mod }`. Moving/renaming a module that declares a
persisted `node` changes its stored `module.Class` key: add
`@archetype_alias("<old.module>.<Node>")` or old graph rows get quarantined.
Runtime data goes to `data/` (`JAC_STUDIO_DATA_ROOT`), external model/dataset
paths live only in `studio.workspace.toml`.
