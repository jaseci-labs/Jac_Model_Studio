## Startup: cold-cache fd clamp

- **Symptom.** The first `./start.sh` after the restructure died with
  `HMR initialization failed: [Errno 24] Too many open files` and
  `Could not start Vite dev server`.
- **Cause.** Traced with a `setrlimit` stack hook. On a cold `.jac/cache`,
  jaclang's module resolver imports `mlx_lm` while compiling `models.sv.jac`,
  before `inference.sv.jac`'s own guard exists. `mlx_lm/utils.py:36` then sets
  `RLIMIT_NOFILE` to `(2048, 4096)`, and a hard limit can't be raised again. The
  dev watcher needs about 13k fds.
- **Fix.** The same monotonic `setrlimit` guard now also lives in
  `scripts/pysite/sitecustomize.py`, which runs at interpreter start.
  `inference.sv.jac` detects it by name and skips its own copy.
- **Verified.** Importing `mlx_lm` without the guard gives (2048, 4096); with it
  the limit stays (65536, unlimited). A cold-cache boot came up in 22s, holding
  13,191 fds. Commit `f9f1c6b`.

## Known issues (not fixed)

- A training job can start while a chat model is resident. Fixing it means
  unloading the chat model when a job takes the lock, which is a behaviour
  change awaiting a decision.
- Project sources can be any readable directory (`add_source`). A per-user
  allowlist is a product decision.
- `jms_chat` is authorized by knowing the project id, by design.
- jac-scale binds 0.0.0.0. Firewall prod (see the Caddyfile note).
- `clsx` and `tailwind-merge` in `jac.toml` are unused; left alone to avoid
  touching the build.
- `remote/supervisor.py` keeps an unreachable `SpheronAPI` path (cloudruns
  always passes `--no-spheron-api`).
- Tests share the project's persisted graph (`.jac/data`, by Jac design).
  Running them while the dev server is up can flake.

## Live run (GPU)

In progress. The GPU was held by another session's function eval until
21:5x; the model-dependent steps (Experiments chat with base and 08,
local MLX train → eval → chat, prod-mode isolation, full browser crawl) run
now and get filled in here.

Incident worth knowing: an end-to-end agent loaded a second 16GB model while
another session's eval held the GPU. Swap hit 41GB and two processes were stuck
in the kernel (`?E`) for 40 minutes before clearing. Rules since then: one MLX
model on the machine at a time, the `/tmp/jac-gpu.lock` owner file, and no
automatic server restarts.
